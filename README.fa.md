# V2Ray Desk

پنل فارسی و انگلیسی برای اوبونتو: فهرست عمومی، مدیریت با رمز، ورود گروهی لینک، Real Delay واقعی از داخل Xray،
تشخیص کشور خروجی، تست HTTP جمینای، فیلتر، ویرایش، حذف انتخابی و دریافت فایل لینک‌ها.

## نصب

روی Ubuntu 22.04 یا جدیدتر با معماری x86_64 یا ARM64:

```bash
unzip v2ray-desk.zip
cd v2ray-panel
sudo bash install.sh
```

نصاب IP یا دامنه و حالت رمز خودکار/دستی را می‌پرسد و رمز جدید را یک بار نمایش می‌دهد.
Xray نسخهٔ ثابت v26.10.17 از مخزن رسمی دانلود و SHA-256 آن بررسی می‌شود.
Python، محیط مجازی، Nginx، گواهی HTTPS و سرویس systemd نصب می‌شوند.

پورت آزاد تصادفی و مسیر تصادفی ۲۰ کاراکتری انتخاب و آدرس کامل چاپ می‌شود:
`https://SERVER_IP:RANDOM_PORT/RANDOM_PATH/`

در وب با دکمهٔ English / فارسی زبان عوض می‌شود. منوی انتخاب کشور فقط نتایج همان کشور
را نشان می‌دهد. کشورهای موجود پس از تست واقعی مشخص می‌شوند.

گواهی پیش‌فرض خودامضاست؛ مرورگر هشدار اعتماد می‌دهد. اثر انگشت گواهی در پایان نصب چاپ
می‌شود. برای استفاده با دامنه، گواهی معتبر را جایگزین مسیرهای
`/etc/v2ray-desk/cert.pem` و `/etc/v2ray-desk/key.pem` کنید و Nginx را reload کنید.
نسخهٔ کلید خصوصی باید فقط در اختیار root باشد.

اگر UFW فعال است، بدون تغییر قانون SSH، پورت پنل را باز کنید:

```bash
sudo ufw allow PORT/tcp
```

به جای PORT پورت چاپ‌شده را بنویسید. فایروال ارائه‌دهندهٔ سرور هم باید این پورت را اجازه دهد.
برای انتخاب پورت‌های دیگر:

```bash
sudo PANEL_HTTPS_PORT=9443 PANEL_BACKEND_PORT=18081 bash install.sh
```

## روش تست

- روش Real Delay مطابق الگوریتم [v2rayN](https://github.com/2dust/v2rayN/blob/57f17d5939e88c8e643ab49b90869d637765e75a/v2rayN/ServiceLib/Handler/ConnectionHandler.cs#L69)
  است: دو GET کامل با یک کلاینت و اتصال قابل استفادهٔ مجدد، با مکث ۱۰۰ میلی‌ثانیه بعد از هر درخواست؛ کمترین زمان مثبت نمایش داده می‌شود.
- مقصد پیش‌فرض `https://www.google.com/generate_204` است؛ Gstatic و Cloudflare هم قابل انتخاب‌اند.
  مهلت پیش‌فرض پنج ثانیه برای مجموع دو درخواست و مکث‌هاست. خطا یا پایان مهلت، تست را ناموفق می‌کند.
  پاسخ‌ها حداکثر یک مگابایت و ده تغییر مسیر مجاز دارند.
- مانند v2rayN، پاسخ HTTP حتی 403 هم زمان دارد؛ نتیجهٔ دسترسی جمینای جدا نمایش داده می‌شود.
  با نگه‌داشتن نشانگر روی تأخیر، زمان هر دو درخواست و کدهای HTTP دیده می‌شود.
- تست تکی و گروهی از یک زمان‌سنج استفاده می‌کنند. زمان اجرای Xray، تشخیص کشور و بررسی جمینای داخل Real Delay نیست.
  نتایج ذخیره‌شده با روش قدیمی، تا تست دوباره با برچسب «اندازه‌گیری قبلی» مشخص می‌شوند.
- در هر دسته یک هستهٔ Xray مشترک با پورت SOCKS و مسیر outbound اختصاصی برای هر کانفیگ اجرا می‌شود؛ هیچ خروجی مستقیم جایگزین وجود ندارد.
  کانفیگ‌های نامعتبر فقط با اعتبارسنجی جدا می‌شوند؛ موارد معتبر دوباره با یک هسته و همان تعداد کارگر موازی تست می‌شوند تا یک تنظیم نامعتبر، تست شبکهٔ بقیه را به گروه‌های کوچک تقسیم نکند.
- کشور از `loc` و IP خروجی از `ip` پاسخ Cloudflare استخراج می‌شود.
  این کشور، کشور خروجی واقعی تست است و لزوماً با محل IP ورودی سرور یکسان نیست.
- اگر کانفیگ پاسخ ندهد، کشور «نامشخص» می‌ماند؛ نام کانفیگ مبنای تشخیص کشور نیست.
- تست HTTPS جداگانهٔ `https://gemini.google.com/app` از همان پروکسی انجام می‌شود.
  403، 429، 200، انتقال به ورود، سایر کدها و خطای اتصال جدا هستند.
  403 علت دقیق (کشور، تشخیص ربات یا محدودیت دیگر) را ثابت نمی‌کند.
  پاسخ 200 فقط پاسخ وب است و تضمین استفاده از حساب یا مدل‌های جمینای نیست.
- نتایج از محل سرور اوبونتو به دست می‌آیند؛ نتیجهٔ اینترنت گوشی یا رایانه ممکن است متفاوت باشد.
- خطای هسته/قالب با «بدون پاسخ» متفاوت است. حذف بدون‌پاسخ‌ها فقط موارد failed در فیلتر فعلی
  را حذف می‌کند و موارد تست‌نشده یا خطای هسته را نگه می‌دارد.
- وقتی گروه‌بندی کشور روشن است، مرتب‌سازی Real Delay داخل هر کشور است.
  برای مرتب‌سازی سراسری، تیک گروه‌بندی کشور را بردارید.
- از ۱ تا ۱۲۸ تست موازی پشتیبانی می‌شود؛ گزینه‌های ۶۴، ۱۰۰ و ۱۲۸ هم در پنل موجودند و پیش‌فرض ۸ است. صف ۱۰۰۰۰ کانفیگ پشتیبانی می‌شود.
  برای مقایسهٔ تأخیر ۱ تا ۴ و برای صف بزرگ ۸ تا ۱۲۸ تست هم‌زمان انتخاب کنید؛ فشار بیشتر سرور ممکن است تأخیر را بالا ببرد.
  فقط ردیف‌های تغییرکرده از سرور دریافت می‌شوند و هر صفحه ۵۰ ردیف دارد.
  توقف، موارد صف را دست‌نخورده می‌گذارد و درخواست‌های HTTP در حال اجرای Real Delay، کشور و جمینای را سریع لغو می‌کند.
  پایان دسته ممکن است همچنان منتظر حل DNS یا راه‌اندازی و بررسی تنظیمات Xray بماند.

## ورودی‌های پشتیبانی‌شده

لینک‌های `vless://`، `vmess://` (JSON به صورت Base64)، `trojan://` و `ss://`.
ورود از متن، فایل متنی، متن Base64 یا لینک ساب با امکان دریافت و به‌روزرسانی دستی.
حداکثر ۲۰۰۰ لینک در هر ورود و ۱۰۰۰۰ کانفیگ در پایگاه‌داده.
انتقال‌های TCP، WebSocket، gRPC، HTTPUpgrade و XHTTP پایه، همراه با TLS و REALITY پشتیبانی
می‌شوند. Shadowsocks استاندارد AEAD و 2022 پشتیبانی می‌شود.

JSON کامل Xray، لینک plugin برای Shadowsocks، KCP، QUIC، XHTTP با extra سفارشی،
VMess با alterId غیرصفر و لینک‌هایی که بررسی گواهی TLS را خاموش می‌کنند در این نسخه
پذیرفته نمی‌شوند. تنظیمات اضافی ناشناخته خطای مشخص می‌دهند؛ بدون اطلاع حذف نمی‌شوند.
برای VMess و VLESS از UUID استاندارد استفاده کنید.

## مدیریت

منوی کامل SSH:

```bash
sudo v2ray-desk
```

نمایش مشخصات، انتخاب پورت دستی یا تصادفی، بررسی آزادبودن پورت و HTTPS،
مسیر ورود تصادفی ۱۰/۲۰ کاراکتری یا مسیر دلخواه، تعویض رمز و کنترل سرویس در منو وجود دارد.
برای اجرای مستقیم:

```bash
sudo v2ray-desk info
sudo v2ray-desk set-port random
sudo v2ray-desk set-port 8443
sudo v2ray-desk set-path random10
sudo v2ray-desk set-path random20
sudo v2ray-desk set-path MyPrivatePanel
sudo v2ray-desk check
sudo v2ray-desk password random
```

رمز جدید فقط هنگام ایجاد نمایش داده می‌شود؛ برای رمز فراموش‌شده از بازنشانی استفاده کنید.
تست پورت از خود سرور، دسترسی همهٔ کاربران بیرونی را تضمین نمی‌کند؛ فایروال دیتاسنتر جداست.
منوی SSH هنگام تغییر پورت، اگر UFW از قبل فعال باشد، قانون پورت جدید را اضافه می‌کند
و هیچ قانون SSH یا قانون قدیمی را حذف نمی‌کند.

```bash
sudo systemctl status v2ray-desk
sudo journalctl -u v2ray-desk -n 100 --no-pager
sudo systemctl restart v2ray-desk
sudo -u v2ray-desk /opt/v2ray-desk/venv/bin/python /opt/v2ray-desk/manage.py reset-password --data /var/lib/v2ray-desk
```

رمز در پایگاه‌داده به صورت scrypt ذخیره می‌شود. تغییر رمز همهٔ نشست‌های قبلی را باطل می‌کند.
نشست‌ها ۸ ساعت اعتبار دارند. پنج ورود ناموفق در ۱۵ دقیقه باعث محدودیت موقت ورود می‌شود.
چون پنل تک‌مدیر است و پشت Nginx قرار دارد، این محدودیت ورود بین درخواست‌ها مشترک است.
CSRF، کوکی Secure و HttpOnly و CSP فعال‌اند. فقط یک فرآیند وب را اجرا کنید؛ صف تست در حافظه است.

مسیر داده: `/var/lib/v2ray-desk/panel.sqlite3`. کانفیگ‌ها شامل رمز/UUID هستند و در دیسک
رمزگذاری نشده‌اند؛ داده و بکاپ را خصوصی نگه دارید. سرویس با کاربر اختصاصی و دسترسی محدود اجرا می‌شود.
صفحهٔ اصلی عمداً همهٔ کانفیگ‌های ذخیره‌شده و لینک کامل آن‌ها را بدون ورود نمایش می‌دهد؛
هر کسی آدرس پنل را داشته باشد می‌تواند کانفیگ‌ها را کپی کند. لینک ساب‌ها، تنظیمات و عملیات مدیریتی همچنان رمز می‌خواهند.
می‌توان چند ردیف را در صفحه‌های مختلف انتخاب و لینک‌ها را یکجا کپی کرد. تغییر جست‌وجو یا فیلتر، انتخاب‌ها را با اعلان پاک می‌کند. هر درخواست کپی حداکثر ۵۰۰ شناسه دارد.
در Linux/POSIX، هنگام آماده‌سازی، مجوز پوشهٔ داده به `0700` و مجوز پایگاه‌داده و فایل‌های
جانبی journal، WAL و shared-memory به `0600` تنظیم می‌شود؛ مجوز فایل‌های موجود نیز اصلاح می‌شود.
تست آدرس خصوصی، loopback و رزروشده مجاز نیست.

بکاپ سازگار از SQLite حتی هنگام فعال بودن WAL:

```bash
sudo systemctl stop v2ray-desk
sudo cp -a /var/lib/v2ray-desk /var/lib/v2ray-desk-backup
sudo systemctl start v2ray-desk
```

نصاب فایل‌های داده را حفظ می‌کند. برای ارتقا ابتدا بکاپ بگیرید.
برای پاک کردن سرویس، ابتدا آن را stop و disable کنید و فایل اختصاصی
`/etc/nginx/conf.d/v2ray-desk.conf` را حذف و Nginx را reload کنید.
پوشهٔ داده را فقط وقتی حذف کنید که دیگر به کانفیگ‌ها نیاز ندارید.

## توسعه و تست

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt pytest
python manage.py init --generate
PANEL_COOKIE_SECURE=0 python manage.py serve
```

گزینهٔ `PANEL_COOKIE_SECURE=0` فقط برای توسعه روی localhost است.

```bash
python tools/install_xray.py --destination /tmp/v2ray-desk-xray
XRAY_TEST_BIN=/tmp/v2ray-desk-xray python -m pytest -q
node --test tests/test_frontend.js tests/test_public_frontend.js
```

تست‌های رابط کاربری در CI با Node.js 24 اجرا می‌شوند و به بستهٔ npm نیاز ندارند.
آزمون‌های خودکار قالب‌ها، احراز هویت، CSRF، حذف محدود، بازنشانی نتیجه پس از ویرایش،
طبقه‌بندی پاسخ‌های جمینای، محدودیت تست آدرس خصوصی و ارتباط واقعی از طریق Xray را بررسی می‌کنند.
مهلت پاسخ‌های آهسته، لغو درخواست، سقف دادهٔ فشرده، مجوز خصوصی فایل‌ها در POSIX،
بازنشانی فیلتر کشور و کنترل‌های ساب هنگام انتظار نیز تست می‌شوند.

## مدیریت ساب‌ها

از «مدیریت ساب‌ها»، نام و لینک HTTP/HTTPS را وارد و «افزودن و دریافت» را انتخاب کنید.
فهرست متنی و Base64 پشتیبانی می‌شود: هر ساب حداکثر ۴ مگابایت و ۲۰۰۰ لینک، حداکثر ۱۰۰ ساب.
هر دریافت مهلت کل ۴۵ ثانیه دارد که حل DNS، تغییر مسیرها، هدر و بدنهٔ پاسخ را شامل می‌شود.
سقف حجم هم روی دادهٔ دریافتی و هم روی دادهٔ بازشده از حالت فشرده اعمال می‌شود.
ساب‌ها را جداگانه، یکجا یا با برنامهٔ روزانه به‌روزرسانی کنید. گزینهٔ فعال بودن، حضور در به‌روزرسانی همه و برنامهٔ روزانه را تعیین می‌کند.
موارد جدید اضافه و موارد حذف‌شده از منبع پاک می‌شوند؛ کانفیگ‌های دستی، ویرایش‌شده یا مشترک با سایر ساب‌ها حفظ می‌شوند.
در صورت خطای دریافت یا نبود کانفیگ پشتیبانی‌شده، فهرست قبلی باقی می‌ماند. لینک‌های نامعتبر یا پشتیبانی‌نشده شمارش می‌شوند.
حذف ساب به‌صورت پیش‌فرض کانفیگ‌ها را نگه می‌دارد؛ گزینهٔ حذف کانفیگ فقط موارد اختصاصی و ویرایش‌نشده را حذف می‌کند.
کانفیگی که دستی حذف شده ولی هنوز در منبع موجود است، با به‌روزرسانی بعدی برمی‌گردد. لینک کامل ساب فقط در فرم ویرایش پس از ورود نمایش داده می‌شود.

فهرست آماده یک بار ۲۷ ساب را اضافه می‌کند: ۸ ساب از [Barry](https://github.com/barry-far/v2ray-config)،
۱۱ بستهٔ V2Ray از [Delta](https://github.com/Delta-Kronecker/V2ray-Config) و ۸ ساب از
[Epodonios](https://github.com/Epodonios/v2ray-configs). دو ساب اول هر منبع خودکار فعال و دریافت می‌شوند؛
بقیه را در مدیریت ساب‌ها فعال کنید. نام سفارشی و وضعیت ساب‌های موجود حفظ می‌شود و ساب حذف‌شده با ری‌استارت برنمی‌گردد.
با «افزودن موارد حذف‌شده» می‌توان فهرست یک منبع را بازگرداند. لینک‌ها در ۲۱ اکتبر ۲۰۲۶ بررسی شده‌اند و ممکن است بعداً تغییر کنند.

تکراری بودن از روی تنظیمات نهایی اتصال تشخیص داده می‌شود، نه نام: صد نام برای یک کانفیگ فقط یک ردیف می‌سازد.
عضویت در چند ساب حفظ می‌شود. فیلتر ساب و پروتکل با کشور و وضعیت ترکیب می‌شود و خروجی متنی یا Base64 قابل انتخاب است.

## برنامهٔ روزانه و حذف خودکار

برنامهٔ روزانه به‌صورت پیش‌فرض ساعت **۰۳:۰۰ تهران** با **۱۰۰ تست هم‌زمان** فعال است.
ابتدا ساب‌های فعال را تازه می‌کند و سپس همهٔ کانفیگ‌ها را برای تأخیر واقعی، کشور خروجی و جیمنای تست می‌کند.
ساعت و تعداد تست هم‌زمان قابل تغییر است. هنگام تست دستی یا دریافت ساب منتظر می‌ماند.
زمان اجرای بعدی، آخرین تلاش و نتیجه ذخیره می‌شود؛ اگر پنل خاموش بوده باشد یک نوبت عقب‌افتاده پس از روشن‌شدن اجرا می‌شود.
قطع اجرای روزانه با ری‌استارت گزارش می‌شود و زمان نوبت بعدی حفظ می‌شود.

**حذف خودکار ابتدا خاموش است** و برای تست دستی و برنامهٔ روزانه جداگانه تنظیم می‌شود.
اگر روشن باشد، دو نوبت پیاپی شکست واقعی اتصال در تست‌های کامل‌شده باعث حذف می‌شود؛ دو درخواست داخل یک تست، یک نوبت حساب می‌شوند.
دریافت هر پاسخ HTTP شمارنده را صفر می‌کند. خطای جیمنای ۴۰۳، هسته، خطای داخلی، اعتبارسنجی گواهی و تست متوقف‌شده باعث حذف نمی‌شوند.
کانفیگ حذف‌شدهٔ خودکار با تازه‌سازی ساب بازنمی‌گردد؛ برای بازگرداندن آن لینک را دستی وارد کنید. ویرایش، شمارندهٔ شکست را صفر می‌کند.

## جدول و اندازهٔ نمایش

پنل عرض ثابت ندارد و از فضای نمایشگر استفاده می‌کند. جدول فشرده با الهام از v2rayN،
نام، پروتکل، آدرس، پورت، انتقال، TLS، کشور، تأخیر و وضعیت جمینای را جدا نشان می‌دهد.
با کلیک عنوان ستون، مرتب‌سازی صعودی/نزولی عوض می‌شود. گروه‌بندی کشور اختیاری است.
برای انتخاب بازه از Shift همراه کلیک روی چک‌باکس و برای ویرایش از دوبار کلیک روی ردیف استفاده کنید.
سرستون هنگام اسکرول ثابت می‌ماند و در نمایشگر کوچک، اسکرول افقی داخل جدول انجام می‌شود.


## ابزارهای تکمیلی

- محدودهٔ تست: همهٔ نتایج یا انتخاب‌شده‌ها، فقط تست‌نشده‌ها، فقط ناموفق‌ها یا هر دو. تنظیمات نامعتبر در تلاش مجدد خودکار کنار گذاشته می‌شوند؛ پس از اصلاح از تست تکی یا «همه» استفاده کنید.
- گزارش CSV شامل تأخیر، کشور، وضعیت HTTP جمینای و توضیح خطاست؛ رمز و لینک کامل کانفیگ را شامل نمی‌شود. فرمول‌های احتمالی در نام‌های واردشده خنثی می‌شوند.
- UUID، کلید و شناسهٔ کوتاه REALITY، ترکیب Flow نوع Vision و کلید Shadowsocks 2022 بررسی می‌شوند. پیش از اجرای تست، خود هسته نیز تنظیمات را با `run -test` بررسی می‌کند. تنظیمات نامعتبر از قطع اتصال و خطای محیط تست جدا نمایش داده می‌شود.
- نسخهٔ نصب‌شدهٔ Xray در پایین پنل وب و دستور `info` در SSH نمایش داده می‌شود.

## تغییرات نسخهٔ ۱.۴

- سقف تست هم‌زمان به ۱۲۸ رسیده و گزینه‌های ۶۴، ۱۰۰ و ۱۲۸ اضافه شده‌اند. پیش‌فرض همچنان ۸ است.
- کادر رمز ورود هنگام انتخاب، تکمیل خودکار و نمایش رمز، عرض کامل و اندازهٔ ثابت خود را حفظ می‌کند.
- صفحهٔ عمومی بدون رمز، فیلتر ساب و پروتکل، ساب‌های آماده و خروجی Base64 اضافه شده‌اند.
- تازه‌سازی و تست کامل روزانه، حذف اختیاری پس از دو شکست و جلوگیری از تکرار بر اساس تنظیمات اتصال اضافه شده‌اند.

## اصلاحات نسخهٔ ۱.۳

- دریافت ساب و بررسی کشور و جمینای مهلت کل مشخص دارند؛ دکمهٔ توقف، درخواست کشور و جمینای را هم لغو می‌کند.
- لینک ناقص VMess و برچسب نامعتبر دامنه خطای جداگانه می‌دهند و مانع پردازش کانفیگ‌های معتبر کنار خود نمی‌شوند. نویسه‌های ویژهٔ رمز در لینک قدیمی Base64 مربوط به Shadowsocks بدون تغییر حفظ می‌شوند.
- اگر کشور انتخاب‌شده دیگر در نتایج نباشد، فیلتر، جدول و انتخاب ردیف‌ها با هم بازنشانی می‌شوند. کنترل‌های ساب هنگام عملیات غیرفعال‌اند و پس از خطا دوباره فعال می‌شوند.
- هنگام آماده‌سازی، مجوز خصوصی پوشهٔ داده و فایل‌های SQLite مطابق توضیح بالا اصلاح می‌شود.
